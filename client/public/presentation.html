Slajd 01 // Problem Inżynieryjny

Paradoks Bezstanowości Współczesnych LLM

Dlaczego powiększanie wag i naiwne okna kontekstowe prowadzą do bankructwa operacyjnego i degradacji uwagi.

1. Fikcja douczania wag
Przeliczanie gradientów (Fine-tuning, LoRA) w czasie rzeczywistym per-użytkownik to błąd ekonomiczny i sprzętowy. Wymaga dedykowanych GPU, niszczy wagi bazowe (Catastrophic Forgetting) i jest niemożliwe przy budżecie $2.00.
2. Złożoność Uwagi O(N²)
Upychanie całej historii rozmów do promptu powoduje kwadratowy wzrost kosztów pamięci KV-Cache, wzrost latencji (Time-to-First-Token) i syndrom Lost in the Middle – model gubi fakty z początku sesji.
3. Bariera Ekonomiczna
Użycie modeli Frontier (Claude 3.5 / GPT-4o) przy $2.00 na użytkownika wystarcza zaledwie na 30–50 zapytań. System kognitywny bez kontroli kosztów tokenów bankrutuje w pierwszej godzinie działania.

Slajd 03 // Topologia Systemu

Pętla Orchestrator – Workers Pipeline

Architektura wieloagentowa rozdzielająca ścieżkę krytyczną (Fast-Path) od analityki w tle (Slow-Path).

1. CostGuard ($2.00 Safe)
Ścisła rejestracja tokenów (prompt/completion) per zapytanie. Wylicza koszt z dokładnością do $0.000001 USD. Odcina operacje asynchroniczne przy rezerwie poniżej $0.01 USD.
2. Fast-Path: Persona Worker
Model gemini-2.5-flash ze streamingiem SSE. Implementuje tożsamość "Aura", konstytucję etyczną oraz Self-System Awareness: świadomość topologii UI (Rozmowa, Mózg, Budżet, Pauza) i dynamiczną refleksję salda tokenów.
3. Slow-Path: Memory Worker & Queue
Model gemini-2.5-flash-lite wywoływany asynchronicznie. Kolejka FIFO (MemoryTaskQueue), bufor TransientMemoryBuffer oraz Self-Healing JSON Extractor eliminują wyścigi asynchroniczne i uszkodzenia składni.
Hybrid Memory Ranker (BM25 + Recency)
Zastąpienie sztywnego LIMIT 40 dynamicznym scoringiem semantycznym (BM25 + TF-IDF + waga świeżości + boost korekt). Redukcja narzutu promptu o ~60% przy wzroście precyzji kontekstu.
Zero-Cost Verification (Wikipedia REST API)
Zapytania encyklopedyczne nie zużywają płatnych tokenów modeli – worker odpytuje oficjalny endpoint Wikipedii, parsuje abstrakt i buforuje go w SQLite. Koszt operacji: 0.000000 USD.

Slajd 05 // Skalowanie Systemowe

Brutalny Audyt Skalowania do 10 000 000 Użytkowników

Identyfikacja wąskich gardeł wdrożenia produkcyjnego w skali globalnej oraz plan migracji.

1. Kolaps I/O SQLite
Wąskie gardło: Pojedynczy plik bazy SQLite ulegnie zablokowaniu (Write Lock Contention) przy równoległych zapisach faktów przez miliony workerów.

Rozwiązanie: Migracja do architektury Tenant-per-Database (np. libSQL/Turso) – każdy użytkownik posiada własny mikro-plik bazy danych synchronizowany brzegowo (Edge).
2. Wyścig Asynchroniczny
Wąskie gardło: Eventual Consistency – jeśli użytkownik wyśle kolejną wiadomość w ciągu 400 ms, MemoryWorker może nie zdążyć utrwalić faktu w bazie przed budową nowego promptu.

Rozwiązanie: Wprowadzenie bufora In-Memory Session Cache (Redis/Dragonfly) na poziomie sesji gniazda SSE.
3. Wąskie Gardło Bramki API
Wąskie gardło: Zależność od OpenRouter stwarza Single Point of Failure oraz ryzyko wyczerpania limitów TPM/RPM przy masowym ruchu.

Rozwiązanie: Wdrożenie własnego klastra vLLM (FP8/INT4) na dedykowanych węzłach GPU, a OpenRouter wyłącznie jako elastyczny fallback.
Slajd 06 // Architektura Dual-Engine & Local-First

Dual-Engine: Node.js Backend vs Browser-Native (GitHub Pages)

Eliminacja kosztów infrastrukturalnych poprzez architekturę Local-First z pamięcią IndexedDB.

Tier A: Server-Side Engine (Node 24 + Fastify)
  • Magazyn: Natywny node:sqlite (zero zewnętrznych zależności C++).
  • Streaming: Server-Sent Events (SSE) z reply.hijack() i buforem chunków.
  • Zastosowanie: Środowiska dedykowane, instancje korporacyjne, centralny audyt ledgerów.
Tier B: Browser-Native Engine (GitHub Pages Portfolio)
  • Magazyn: IndexedDB (BrowserCognitiveStore) – wzorzec Repository Pattern.
  • Komunikacja: Bezpośrednie zapytania CORS do OpenRouter i REST API Wikipedii.
  • Sandbox Mode: Autonomiczna symulacja dialogu i ekstrakcji faktów bez klucza API.
  • Koszt hostingu: $0.00 / miesiąc (czysty hosting statyczny).

Slajd 07 // Architektura Neuronowa: KAN + SOM + EWC

Fizyczny Rdzeń KAN: Uczące się Splajny i Routing Topologiczny

Zastąpienie brutalnej siły gęstą reprezentacją nieliniową na krawędziach grafu oraz ochroną pamięci.

1. Nieliniowości KAN (B-Splines)
Zasada: Zastąpienie wag $W \cdot x$ sumą splajnów na krawędziach: $\phi(x) = w_b \text{Mish}(x) + w_s \sum c_p B_p(x)$.

Zysk: 696 320 parametrów splajnów (95.1% modelu). Zdolność aproksymacji 10x większego klasycznego MLP.
2. Routing Topologiczny (SOM MoE)
Zasada: Embedding trafia na siatkę SOM $W \in \mathbb{R}^{K \times d}$. Gaussowski kernel aktywuje wyłącznie Top-2 ekspertów KAN.

Zysk: Redukcja kosztu inferencji o 75% FLOPs przy zerowym rozmyciu wiedzy semantycznej.
3. Pamięć EWC & Optymalizacja SAM
Zasada: Macierz Informacji Fishera ($F_i$) zamraża wagi składni ($\lambda = 200$), podczas gdy optymalizator SAM szuka płaskich minimów.

Zysk: Eliminacja katastroficznego zapominania przy ciągłym douczaniu nowymi faktami.
