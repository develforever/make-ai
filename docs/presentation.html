Slajd 01 // Problem Inżynieryjny

Paradoks Bezstanowości Współczesnych LLM

Dlaczego powiększanie wag i naiwne okna kontekstowe prowadzą do bankructwa operacyjnego i degradacji uwagi.

1. Fikcja douczania wag
Przeliczanie gradientów (Fine-tuning, LoRA) w czasie rzeczywistym per-użytkownik to błąd ekonomiczny i sprzętowy. Wymaga dedykowanych GPU, niszczy wagi bazowe (Catastrophic Forgetting) i jest niemożliwe przy budżecie $2.00.
2. Złożoność Uwagi O(N²)
Upychanie całej historii rozmów do promptu powoduje kwadratowy wzrost kosztów pamięci KV-Cache, wzrost latencji (Time-to-First-Token) i syndrom Lost in the Middle – model gubi fakty z początku sesji.
3. Bariera Ekonomiczna
Użycie modeli Frontier (Claude 3.5 / GPT-4o) przy $2.00 na użytkownika wystarcza zaledwie na 30–50 zapytań. System kognitywny bez kontroli kosztów tokenów bankrutuje w pierwszej godzinie działania.

Slajd 03 // Topologia Systemu

Pętla Orchestrator – Workers Pipeline

Architektura wieloagentowa rozdzielająca ścieżkę krytyczną (Fast-Path) od analityki w tle (Slow-Path).

1. CostGuard ($2.00 Safe)
Ścisła rejestracja tokenów (prompt/completion) per zapytanie. Wylicza koszt z dokładnością do $0.000001 USD. Odcina operacje asynchroniczne przy rezerwie poniżej $0.01 USD.
2. Fast-Path: Persona Worker
Model gemini-2.5-flash ze streamingiem SSE. Implementuje tożsamość "Aura", konstytucję etyczną oraz Self-System Awareness: świadomość topologii UI (Rozmowa, Mózg, Budżet, Pauza) i dynamiczną refleksję salda tokenów.
3. Slow-Path: Memory Worker & Queue
Model gemini-2.5-flash-lite wywoływany asynchronicznie. Kolejka FIFO (MemoryTaskQueue), bufor TransientMemoryBuffer oraz Self-Healing JSON Extractor eliminują wyścigi asynchroniczne i uszkodzenia składni.
Hybrid Memory Ranker (BM25 + Recency)
Zastąpienie sztywnego LIMIT 40 dynamicznym scoringiem semantycznym (BM25 + TF-IDF + waga świeżości + boost korekt). Redukcja narzutu promptu o ~60% przy wzroście precyzji kontekstu.
Zero-Cost Verification (Wikipedia REST API)
Zapytania encyklopedyczne nie zużywają płatnych tokenów modeli – worker odpytuje oficjalny endpoint Wikipedii, parsuje abstrakt i buforuje go w SQLite. Koszt operacji: 0.000000 USD.

Slajd 05 // Architektura Skalowania Tier-1

Distributed Data Fabric, Worker Threads & Vector ANN

Eliminacja wąskich gardeł monolitu: rozproszony libSQL/Turso, izolacja obliczeń KAN w Worker Threads oraz wektorowa pamięć semantyczna ANN.

1. libSQL / Turso Data Fabric
Architektura: Przejście z monolitycznego pliku na rozproszony Tenant-per-Database z @libsql/client.

Zysk: Całkowita eliminacja Write Lock Contention, lokalne repliki brzegowe (Embedded Replicas), zerowa latencja odczytu i nieograniczona skalowalność do 10M+ najemców.
2. KAN-Cognitive Core v2 & Worker Threads
Architektura: Pełna integracja z głównym potokiem OrchestratorEngine.executeStep. Ewaluacja polityki evaluatePolicy przed generowaniem promptu steruje dynamicznym memoryTopK w MemoryRanker oraz wzmacnia nadzór moralny (ethicsWeight > 0.7) w PersonaWorker. Asynchroniczne douczanie ze sprzężeniem zwrotnym applyReward (satysfakcja, koszty, spójność faktów).

Zysk: 0 ms blokowania pętli zdarzeń. Dynamiczna telemetria czasu rzeczywistego w /api/neural/telemetry z hybrydowym łączeniem profili i wag.
3. Vector Memory ANN
Architektura: Wielowymiarowe embeddingi semantyczne z natywnym indeksem HNSW / ANN oraz hybrydowym rankerem (BM25 + Cosine Vector Search).

Zysk: Sub-milisekundowe wyszukiwanie faktów kognitywnych w zbiorach >100k wpisów bez liniowego skanowania tabeli i bez halucynacji.

Slajd 06 // Autonomiczna Konsolidacja Wiedzy (Tier-1 Cognitive Dreamer)

Idle Dream Consolidation: Autonomiczna Synteza Aksjomatów KAN

Odkrywanie synergii logicznych i wnioskowanie pośrednie w czasie bezczynności systemu bez zużycia tokenów LLM i bez ingerencji użytkownika.

Potok Kognitywnej Konsolidacji (DreamConsolidator)
Gdy użytkownik pozostaje bezczynny przez ponad 25 sekund (okresowe badanie pętli co 10s), system autonomicznie uruchamia asynchroniczny cykl syntezy:
  • Śledzenie Bezczynności: notifyUserActivity() w executeStep natychmiast resetuje licznik przy każdym komunikacie użytkownika.
  • Selekcja Par (Zero-Waste): getUnconsolidatedFactPairs() pobiera aktywne fakty o różnej kategorii/podmiocie z wykluczeniem par zbadanych (tabela consolidated_fact_pairs).
  • Wnioskowanie KAN: Dedukcja relacji tranzytywnych (A → B ∧ B → C ⇒ A → C) oraz aproksymacja energii B-splajnów w osobnym wątku.
  • Utrwalanie Aksjomatów: Zapis do learned_facts z kategorią synergy_axiom, embeddingiem 32D i eliminacją duplikatów.

Zero-Token Inference
Synteza nowej wiedzy nie zużywa budżetu $2.00 ani zewnętrznych modeli. Całość obliczeń realizowana jest lokalnie w wątku KAN z latencją <5 ms per para.
Ochrona B-Tree i Pamięci
Tabela consolidated_fact_pairs z kluczem unikalnym eliminuje redundantne badanie zbadanych już par, chroniąc bazę przed zbędnymi cyklami I/O.
Pełna Śledzalność (Traceability)
Każdy aksjomat utrwala sourceFactIds w kolumnie metadata. W razie unieważnienia faktu bazowego, system koryguje powiązane aksjomaty.

Slajd 08 // Architektura Neuronowa: KAN + SOM + EWC

Fizyczny Rdzeń KAN: Uczące się Splajny i Routing Topologiczny

Zastąpienie brutalnej siły gęstą reprezentacją nieliniową na krawędziach grafu oraz ochroną pamięci.

1. Nieliniowości KAN (B-Splines)
Zasada: Zastąpienie wag $W \cdot x$ sumą splajnów na krawędziach: $\phi(x) = w_b \text{Mish}(x) + w_s \sum c_p B_p(x)$.

Zysk: 696 320 parametrów splajnów (95.1% modelu). Zdolność aproksymacji 10x większego klasycznego MLP.
2. Routing Topologiczny (SOM MoE)
Zasada: Embedding trafia na siatkę SOM $W \in \mathbb{R}^{K \times d}$. Gaussowski kernel aktywuje wyłącznie Top-2 ekspertów KAN.

Zysk: Redukcja kosztu inferencji o 75% FLOPs przy zerowym rozmyciu wiedzy semantycznej.
3. Pamięć EWC & Optymalizacja SAM
Zasada: Macierz Informacji Fishera ($F_i$) zamraża wagi składni ($\lambda = 200$), podczas gdy optymalizator SAM szuka płaskich minimów.

Zysk: Eliminacja katastroficznego zapominania przy ciągłym douczaniu nowymi faktami.

Slajd 09 // Architektura Wielosesyjna & Graf Wiedzy

Hierarchia Sesji i Transfer Wiedzy Międzysesyjnej

Eliminacja monolitycznej historii: izolacja kontekstów per-sesja, katalogowanie i kontrolowany transfer wiedzy (@mention) bez zanieczyszczania uwagi.

Kluczowe Mechanizmy Zarządzania Sesjami
  • Izolacja Per-Sesja: Wiadomości indeksowane kluczem session_id w B-Tree SQLite WAL oraz IndexedDB v2. Zero wycieków między wątkami.
  • Dwufazowe Auto-Tytułowanie: Natychmiastowa heurystyka w O(1) + asynchroniczne streszczenie LLM (3–5 słów) po zakończeniu strumienia.
  • Cykl Życia Sesji: Przypinanie (Pinning) na szczycie listy, archiwizacja (Soft Archive) oraz kaskadowe usuwanie powiązanych rekordów.
  • Grupowanie w Katalogi: Tworzenie, edycja i bezpieczne usuwanie folderów z zachowaniem sesji.
  • Globalne Wyszukiwanie: Szybkie przeszukiwanie tytułów i treści z generowaniem dynamicznych wycinków tekstu (snippets).
